# 원료서류 분류 지침

라벨크래프트 "서류 분석 에이전트"가 업체 업로드 원료서류를 **내용 기반으로** 정확히
분류하기 위한 실무 지침이다. 헤르메스 봇이 현장에서 겪은 오분류 사고를 규칙으로 흡수했다.

이 시스템의 1순위 타깃은 **한글표시사항**이다(요구사항 문서: "그중 한글표시사항만
추출·등록"). 나머지 유형은 (a) 한글표시사항과 혼동되지 않게 걸러내고 (b) 교차검증·이력
추적에 쓰기 위해 함께 분류한다.

> **핵심 포지션 (label-pilot CLAUDE.md와 정합):** 이 에이전트는 **후보를 제시**할 뿐이며,
> 최종 확정은 **업체 담당자(④ 확인 단계)** 와 **내부 담당자(확인 대기 큐)** 가 한다.
> 자동 분류가 틀리거나 못 찾아도 **제출을 막지 않는다.** 규정 수치·조항은 기억으로
> 지어내지 않고 불확실하면 "확인 필요"로 표기한다.

## 개정 이력

- **v1.1.0 (2026-07-22)** — 외부 교차검증(Codex) 지적 13건 반영.
  - 품목제조보고서(일반식품) vs 품목제조신고서/신고증(건강기능식품) 행정 체계 분리(하위 코드·키워드 분리, §2-5). **법 조항 번호는 미검증이라 인용하지 않음 — "확인 필요"로 둠**(CLAUDE.md 원칙 2).
  - 뭉쳐 있던 `certificate`(인증서류) 해체: ①인증기관 발급 인증서(할랄·코셔·유기) ②공급자 자체 선언서/확인서를 별도 유형 `supplier_declaration`으로 신설 ③방사능·잔류농약 시험을 COA 계열 하위 태그로 이동 ④GMP·HACCP·ISO를 제조시설/품질시스템 인증(`facility_certificate` 하위 태그)으로 명시(§2-2·§2-8·§2-9).
  - 한글표시사항 채점 키워드 재설계: 단독 일반어(유형·소재지·중량·용량·원료명) 제거, 강한 조합으로 교체, **음성 규칙 신설**(§4-1).
  - §4-2 동점 처리에서 "한글표시사항 무조건 우선" 삭제 → 유형 고유 강신호(음성 규칙) 우선 → 경합 시 `미상`.
  - "Certificate"·"Nutrition Facts" 단독 신호 금지(구체 인증명·시험기관 흔적 필수).
  - 수입 서류(관세청 vs 식약처) 하위 태그 분리(§2-4).
  - 비원료 키워드 보강(Invoice·Packing List·납품서·사업자등록증 등)·표제 강신호 1종 확정(§2-13).
  - 빈출 서류 정식 등재: 제조공정도·원료 조성표·공급자 선언서·잔류농약 시험(§2-10~§2-12, §2-2·§2-8).
  - 스캔본 선분류에 첫 페이지 0점 시 마지막+중간 페이지 추가 샘플링(§4-3).
  - 파일명은 UI 표시·참고용으로만, **판정 로직 사용 금지**로 문구 정리(§1-1·§2).
  - 임계값 경계 "N종 이상(≥N)"으로 전 문서 통일, §4-5 "초과"→"이상" 정정.
  - taxonomy 유형 수 재계산·표기 통일(§2, unknown 포함 여부 명시).
- **v1.0.0 (2026-07-22)** — 최초 작성. 헤르메스 실전 분류 노하우 이식, 하드코딩 정보 제거.

## 1. 분류 절대 원칙

각 원칙 끝에 출처를 명기한다.

1. **파일명·확장자로 판정 금지 — 내용(추출 텍스트)으로만 판별. 파일명은 판정 로직에 일절 쓰지 않는다.**
   업체 파일명은 제각각이다("스캔001.pdf", "붙임2.pdf", "제품자료.pdf", "거래명세표.pdf").
   파일명은 **확인 화면 UI 표시·담당자 참고용**으로만 쓴다 — 유형 확정, 동점 해소,
   가중치 등 **어떤 판정 로직에도 투입하지 않는다.** 유형 판정은 오직 추출 텍스트의
   키워드 채점(§4)으로만 한다.
   (출처: 포털 설계 "표시사항 파일 판별 — 파일명이 아니라 내용으로" / 헤르메스 P0 규칙 6
   "파일명만 보고 판단 금지 — 내용 확인", 2026-04-01 사고)

2. **파일 1건씩 순차 처리 — 일괄 분류 금지.**
   여러 파일을 한 번에 뭉뚱그려 라벨링하지 않는다. 각 파일(합본 PDF는 각 페이지 묶음)을
   독립적으로 채점한다. 브라우저 메모리·OCR 속도 관리에도 순차 처리가 유리하다.
   (출처: 헤르메스 P0 규칙 7 "일괄 분류 금지 — 원료 1개씩 순차 처리" / 포털 설계
   "해제·OCR은 파일 단위 순차 처리")

3. **원본 무변경 — 해시로만 참조.**
   포털은 원본 파일을 서버로 보내지 않는다. 분류 결과에는 추출 텍스트와 `source_hash`
   (sha256)만 담는다. 원본을 재저장·재생성·변형하지 않는다.
   (출처: 포털 설계 "파일은 인터넷을 타지 않는다"·`source_hash` 무결성 참조 / 헤르메스
   P0 규칙 3 "자체 PDF 생성 금지 — 업체 원본 그대로")

4. **애매하면 단정하지 말고 "미상(사람 확정 필요)" 등급으로.**
   임계값 근처거나 두 유형에 걸치면 억지로 하나로 확정하지 않는다. 신뢰도 3등급 중
   `미상`으로 내보내고 담당자 확정에 맡긴다. 잘못 확정하면 잘못된 서류가 등록·발송된다.
   (출처: label-pilot CLAUDE.md 원칙 4 "후보 제시·확정은 사람" / 헤르메스 2026-06-01
   기존 파일 재사용 사고 — 성급한 확정이 업체에 잘못된 서류 발송으로 이어짐)

5. **자동 분류 실패가 제출을 막으면 안 된다.**
   후보를 못 찾아도 담당자가 전체 텍스트에서 직접 구간을 지정해 제출할 수 있어야 한다.
   분류는 담당자를 **돕는** 장치이지 **막는** 관문이 아니다.
   (출처: 포털 설계 "자동 분류가 못 찾아도 제출이 막히지 않게 한다" / label-pilot
   CLAUDE.md "어설픈 결과 출력 금지"의 반대 방향 — 막지 말고 넘겨라)

6. **최신 제출본 우선 — 과거 분류 결과 재사용 금지.**
   같은 업체·같은 원료라도 이번 제출에 들어온 파일을 그때그때 새로 채점한다. "지난번에
   COA였으니 이번에도 COA" 같은 캐시 판단 금지. 배송·개정마다 서류가 바뀐다.
   (출처: 헤르메스 P0 규칙 0 "기존 폴더 파일 재사용 절대 금지", 2026-06-01 사고
   재발방지 — 이 시스템의 최우선 규칙)

7. **비원료 서류는 분류 단계에서 걸러 표시한다(차단).**
   발주서·거래명세서·세금계산서·견적서·제안서·인보이스·패킹리스트·납품서·사업자등록증 등은
   원료서류가 아니다. "비원료"로 분류해 표시사항 후보에서 제외한다(제출 자체를 막지는
   않되 등록 대상 아님을 명시).
   (출처: 헤르메스 P0 규칙 5 "비원료 서류 원료 폴더 저장 금지", 2026-03-30 신설)

8. **규정 수치·조항을 기억으로 지어내지 않는다.**
   글자 크기·함량 기준·별표 번호·법 조항 번호 등 규정 수치가 분류 근거로 필요하면,
   확인 못 한 값은 "확인 필요"로 표기한다. 유형 분류는 키워드 존재로 판별하며 규정 수치
   판정과 분리한다.
   (출처: label-pilot CLAUDE.md 절대 원칙 2 "학습 기억 속 수치를 검증 없이 박지 않는다")

## 2. 문서 유형 분류 체계 (Taxonomy)

**유형 수: 실질 유형 13종 + `기타/미상`(unknown) 1종 = 총 14종 코드.**
(실질 13종 = 한글표시사항, 시험성적서/COA, 원산지증명서, 수입신고필증, 품목제조보고/신고,
규격서, MSDS, 인증서, 공급자 선언서/확인서, 영양성분 분석서, 제조공정도, 원료 조성표,
비원료. `unknown`은 어디에도 확정 안 되는 폴백이라 실질 유형에는 넣지 않고 별도로 센다.)

각 유형은 ①정의·발급주체 ②본문 식별 키워드(한글 + 영문 표제 변형) ③혼동 유형 구분
규칙으로 기술한다.

키워드는 **추출 텍스트에 그 문자열이 등장하는지**로 채점한다(§4). **파일명은 판정에
쓰지 않는다(원칙 1)** — 이 절에서도 파일명 패턴은 다루지 않으며, 확인 화면에서 담당자에게
보여주는 참고 정보일 뿐이다.

### 2-1. 한글표시사항 ★1순위 타깃 · `korean_label`

| 항목 | 내용 |
|---|---|
| **정의·발급주체** | 원료(또는 완제품)의 한글 표시사항. 제조사/수입사가 작성. label-pilot이 실제로 추출·등록하는 유일한 대상. |
| **본문 식별 키워드** | 제품명, 원재료명(원재료 및 함량), 품목보고번호(품목제조보고번호), 소비기한/유통기한, 내용량, 업소명 및 소재지(제조원/판매원/수입원), 식품유형, 보관방법, 영양성분, 알레르기 유발물질, "부정·불량식품 신고" 문구 |
| **혼동 구분 규칙** | 규격서(SPEC)와 혼동 주의: 표시사항은 **의무표시 키워드가 표시사항 특유 표기 형태로 묶여** 등장(§4-1 강조합). 규격서는 규격 범위값(성상·순도·중금속·미생물의 ≤/≥/N.M.T)이 중심. / 품목제조보고서와 혼동 주의: 배합비율·제조방법 표가 주면 표시사항이 아니다(§4-1 음성 규칙). |

### 2-2. 시험성적서 / COA (Certificate of Analysis) · `coa`

| 항목 | 내용 |
|---|---|
| **정의·발급주체** | 원료 배치(LOT)의 시험 결과. 제조사 QC 또는 공인시험기관 발급. |
| **본문 식별 키워드** | 시험성적서, 성적서, 검사성적서, 분석성적서, COA, Certificate of Analysis, Test Report, 시험항목, 규격(Spec)/결과(Result), 판정(적합/부적합), Lot No / 제조번호, 시험일자, 시험기관 |
| **하위 태그(sub_tags)** | `radioactivity`(방사능 검사성적서: 방사능/becquerel/Bq/세슘/요오드/방사능검사), `pesticide_residue`(잔류농약 시험성적서: 잔류농약, Pesticide Residue, 다종농약다성분) — 두 시험은 인증서가 아니라 **시험기관이 발급한 성적서**이므로 COA 계열로 둔다. |
| **혼동 구분 규칙** | 규격서(SPEC)와 구분: COA는 **특정 LOT의 실측 결과값**(Result 열)과 판정이 있음. SPEC은 규격 범위만 있고 실측·LOT 없음. "결과/Result + LOT + 판정"이 함께 있으면 COA. / 영양성분 분석서와 구분: COA는 안전·품질 항목(중금속·미생물) 위주, 영양성분 분석서는 열량·탄단지 위주. / 방사능·잔류농약은 인증서(2-8)가 아니라 성적서다 — 시험기관 발급·시험일자·성적서번호가 있으면 여기(sub_tags)로. |

### 2-3. 원산지증명서 (Certificate of Origin, C/O) · `certificate_of_origin`

| 항목 | 내용 |
|---|---|
| **정의·발급주체** | 원료·물품의 원산지 증명. 상공회의소·세관·수출국 발급기관. |
| **본문 식별 키워드** | 원산지증명서, Certificate of Origin, Country of Origin, 원산지국가, 수출자(Exporter), 수입자(Importer), 상공회의소, Chamber of Commerce, FTA, 원산지 결정기준 |

## 4. 채점 알고리즘 지침

### 4-1. 의무표시 키워드 채점 (한글표시사항 판별 — 결정적 규칙, LLM 아님)

포털 요구사항의 7종 골격을 쓰되, **단독 일반어를 빼고 표시사항 특유의 표기 형태(강조합)로
재설계**했다(단어 하나로는 성적서·규격서·조성표와 겹치므로).

| # | 의무표시 항목 | 채점 키워드(표시사항 특유 표기만) | 제외한 일반어(단독 사용 금지) |
|---|---|---|---|
| 1 | 원재료명 | 원재료명, 원재료 및 함량 | ~~원료명~~(성분표·조성표와 겹침) |
| 2 | 품목보고번호 | 품목보고번호, 품목제조보고번호 | — (원래 특유어) |
| 3 | 소비기한/유통기한 | 소비기한, 유통기한 | — |
| 4 | 내용량 | 내용량 | ~~중량~~, ~~용량~~(규격서·명세서와 겹침) |
| 5 | 업소명 및 소재지 | 업소명 및 소재지, 제조원, 판매원, 수입원 | ~~소재지~~(사업자등록증·명세서와 겹침) |
| 6 | 식품유형 | 식품유형 | ~~유형~~(성적서 "시험유형" 등과 겹침) |
| 7 | 보관방법 | 보관방법, 냉동보관, 냉장보관, 직사광선을 피하 | ~~보관조건~~(규격서와 겹침) |
| 보조 | 표시사항 고유 문구 | 제품명, "부정·불량식품 신고", 알레르기 유발물질 | — (강신호로 가중) |

- **채점법:** 1~7종 항목 중 몇 **종**이 텍스트에 등장하는지 센다(같은 종 내 여러 변형이
  나와도 1종). 보조 문구는 종 수에 넣지 않고 확정 가중 신호로만 쓴다. 결정적 카운트이며
  LLM을 쓰지 않는다(label-pilot 원칙 1: 판별은 규칙).
- **임계값:** **4종 이상(≥4) = 한글표시사항 후보.** 이 강조합 4종 이상이 함께 나오는
  문서는 사실상 표시사항뿐이라 성적서·규격서·조성표와 강하게 구분된다.
- **★ 음성 규칙(표시사항 배제 강신호):** 아래가 있으면 의무표시 종 수가 임계를 넘어도
  **한글표시사항 후보에서 배제**하고 해당 유형으로 보낸다. 표시사항이 배합·규격 문서 안에
  단어 몇 개로 섞여 오분류되는 것을 막는다.
  - **품목제조보고 강신호:** 배합비율표 / 성분배합비율 / 제조방법 표 / 보고관청 → 품목제조보고서(2-5)
  - **SPEC 강신호:** 실측·LOT 없이 규격 범위값(≤ / ≥ / N.M.T / "이하"·"이상" 기준표)만 → 규격서(2-6)
  - **성적서 강신호:** LOT + Result(결과) + 판정(적합/부적합) → COA(2-2)
- **출처:** 요구사항-업체업로드포털.md "의무표시 키워드 채점(결정적 규칙)" + Codex 지적(단독 일반어 제거·음성 규칙 신설).

### 4-2. 유형별 키워드 사전 + 임계값(제안)

§2의 각 유형 "본문 식별 키워드"를 사전으로 쓴다. 유형별 점수 = 그 유형 키워드 중
등장한 **종 수**. 아래는 초기 제안값이며 실측으로 갱신한다(label-pilot: 가정치는 실측 갱신).
임계값 표기는 전 문서 **"N종 이상(≥N)"** 으로 통일한다.

| 유형 | 후보 임계값(종 수) | 확정 보조 조건 |
|---|---|---|
| 한글표시사항 | 의무표시 4종 이상(§4-1) + 음성 규칙 미해당 | 제품명·원재료명 동시 존재면 가중 |
| 시험성적서/COA | 3종 이상 | "LOT + Result + 판정" 동시 시 확정 강화. 방사능/잔류농약은 sub_tags |
| 원산지증명서 | 2종 이상 | "Certificate of Origin" 또는 "원산지증명서" **표제 필수**(Certificate 단독 금지) |
| 수입신고필증 | 2종 이상 | "관세청/세관/신고번호" → customs, "수입신고확인증/지방식약청" → mfds |
| 품목제조보고/신고 | 2종 이상 | "배합비율/제조방법 표" 존재 시 확정 강화. food_report/hf_report 하위 코드 부여 |
| 규격서(SPEC) | 3종 이상 | 실측·LOT 없이 범위값(≤/≥/N.M.T)만이면 COA와 분리 |
| MSDS | 2종 이상 | "MSDS/SDS" + "유해성·위험성/CAS번호" 시 확정 |
| 인증서 | 구체 인증명 1종 이상 | 할랄/코셔/유기 등 구체명 필수(Certificate 단독 금지). GMP/HACCP/ISO는 facility_certificate 하위 태그 |
| 공급자 선언서/확인서 | 2종 이상 | "선언서/확인서/Declaration" + Non-GMO/BSE·TSE/알레르겐 중 1 |
| 영양성분 분석서 | 2종 이상 | **시험기관 발급 흔적(시험기관명·시험일자·성적서번호) 필수**("영양성분"·"Nutrition Facts" 단독 금지) |
| 제조공정도 | 2종 이상 | "제조공정도/Process Flow" + 공정 단계 어휘 |
| 원료 조성표 | 2종 이상 | 성분명+% 나열, 신고 행정 정보 없음 |
| 비원료(차단) | 표제 강신호 1종 이상(§2-13) 또는 키워드 2종 이상 | 세금계산서는 "공급가액+세액+사업자등록번호" 시 확정 |

- **★ 동점·경합 처리 (Codex 지적 반영 — "한글표시사항 무조건 우선" 삭제):**
  두 유형 점수가 임계값을 함께 넘으면, **유형 고유 강신호(§4-1 음성 규칙 + 각 유형 확정
  보조 조건)를 우선 적용**한다. 예: 표시사항 의무표시 4종이 잡혀도 배합비율·제조방법 표가
  있으면 품목제조보고서가 이긴다(음성 규칙). 강신호로도 갈리지 않고 두 유형이 경합하면
  억지로 하나를 고르지 말고 **`미상`으로 내려 담당자 확정**에 맡긴다(원칙 4).
- **비원료 우선 차단:** 세금계산서·발주서·인보이스 등의 표제 강신호(§2-13)가 뜨면 다른
  유형 점수와 무관하게 `비원료`로 우선 분류(상거래 문서가 표시사항 후보로 새는 것을
  막는다 — S5).

### 4-3. 스캔본 페이지 선분류

- OCR은 느리므로 **전 파일 전체 OCR 금지.** 각 파일 **첫 페이지부터 OCR/추출해 채점**하고,
  후보(어느 유형이든 임계값 근접·이상)로 판정된 파일만 전체 OCR한다.
- **★ 첫 페이지 0점 대비 보완 샘플링 (Codex 지적 반영):** 합본은 첫 페이지가 표지·목차라
  본문 키워드가 없을 수 있다. **첫 페이지 채점이 0(어느 유형에도 신호 없음)이면 "서류 없음"으로
  단정하지 말고, 마지막 페이지 + 중간 1페이지를 추가로 OCR·채점**한 뒤 판단한다. 추가
  샘플에서도 0이면 그때 "표시사항 없음 후보(담당자 확인)"로 넘긴다.
- 표시사항·성적서 등은 보통 1~2페이지라 선분류로 대부분 걸러진다.
- **디지털 PDF는 추출이 순간**이라 전체를 채점해도 무방(선분류 불필요).
- (출처: 포털 요구사항 "1페이지 선분류" + Codex 지적(표지·목차 합본 대비))

### 4-4. 합본 PDF(여러 서류가 한 파일) — 페이지 단위 재채점

업체는 표시사항+COA+원산지 등을 **한 PDF에 합쳐** 보내는 경우가 많다.

- 파일 전체 점수만 보지 말고, **페이지(또는 페이지 묶음) 단위로 §4-1·4-2 재채점**한다.
- 한 파일에서 여러 유형이 각각 임계값을 넘으면, 그 파일의 결과를 **구간(페이지 범위)별
  다중 유형**으로 출력한다(예: p1–2 한글표시사항, p3 COA, p4 원산지증명서).
- 표시사항 구간만 추출 대상으로 표시하고 나머지 구간은 "표시사항 없음"으로 접어 표시.
- 구간 경계가 불확실하면 담당자가 확인 화면에서 드래그로 지정(원칙 5, 포털 ③ 실패 경로).

### 4-5. 신뢰도 3등급 출력

| 등급 | 조건 | 처리 |
|---|---|---|
| **확정(confirmed)** | 임계값 이상 + 확정 보조 조건 충족 + 경합 유형 없음 | 후보로 강하게 제시. 담당자 확인은 여전히 필수. |
| **후보(candidate)** | 임계값은 이상이나 확정 보조 조건 미충족 또는 약한 경합 | "이 유형으로 보임"으로 제시, 담당자 확인 유도. |
| **미상(unknown)** | 임계값 미달, 또는 근소 경합(강신호로 안 갈림), 또는 약어·코드명으로 원료명 불명 | "미상(사람 확정 필요)". 제출은 막지 않음(원칙 5). |

- 임계값 경계는 **"이상"(≥)** 으로 통일한다(§4-2와 일치). "임계값 초과(>)" 표현은 쓰지 않는다.
- 어떤 등급이든 **최종 확정은 사람**(포털 ④ 담당자 → 내부 확인 대기 큐). 시스템은
  항상 **후보 제시자**다(label-pilot 원칙 4).

## 5. 교차 검증

분류 확정 전/후로 다음을 대조해 오분류·오등록을 잡는다.

1. **품목명 일치 확인 (약어·코드명 주의 — S3).**
   - 표시사항의 제품명·품목명, COA/규격서의 품명과 담당자 입력 `ingredient_name`을 대조.
   - **약어·공급자 코드명은 정식 품목명이 아니다**(PST-N=팔라티노스 사례). 약어로 보이면
     원료명을 확정하지 말고 `미상`으로 두고 담당자 확인.

2. **서류 발급주체 vs 업로드 업체 대조.**
   - 서류 상단 발급사(제조원/판매원/시험기관/세관/인증기관)와 이 서류를 올린 업체 토큰의
     업체명을 비교. 크게 다르면(예: 타사 제조 서류) 메모 필드에 플래그를 남겨 담당자가 확인.
   - 대조는 **경고 신호**일 뿐 자동 차단하지 않는다(제출은 막지 않음, 원칙 5).

3. **추출 대상 필드 목록 (분류 후 함께 뽑아 검증·이력에 사용).**

   | 필드 | 설명 |
   |---|---|
   | LOT / 제조번호 | 배치 식별. COA·표시사항 대조에 사용 |
   | 제조일자 | 제조 시점 |
   | 유효기간 / 소비기한 | 만료 관리 |
   | 시험일자(성적서) | COA 발급 시점 |
   | 발급기관/발급사 | 발급주체 대조(위 2번) |
   | 품목명/제품명 | 품목명 대조(위 1번) |

   - 위 필드는 **분류 보조·이력용**이며, 값 추출 실패가 분류·제출을 막지 않는다.

## 6. 분류 결과 JSON 스키마 (제안)

포털 전송 스키마(`items[]`의 `source_filename`·`source_hash`·`extract_method`·
`ingredient_name`·`label_text`·`operator_confirmed` 등)와 **필드명이 충돌하지 않도록**
분류 결과는 별도 네임스페이스(`classification`)로 감싼다. 포털 제출 JSON에 이 블록을
추가하는 형태를 상정한다.

```jsonc
{
  "classification": {
    "schema_version": "1.1.0",
    "classified_at": "2026-07-22T14:00:00+09:00",
    "source_filename": "제품자료.pdf",      // 포털 스키마와 동일 값(UI 참고용, 판정 근거 아님)
    "source_hash": "sha256:...",             // 포털 스키마와 동일 값(원본 무변경 참조)
    "extract_method": "pdfjs",               // pdfjs | tesseract | manual (포털과 동일 어휘)
    "is_compound_pdf": true,                 // 합본 PDF 여부(§4-4)
    "segments": [                            // 파일/페이지 구간별 분류 결과
      {
        "page_range": "1-2",                 // 합본이 아니면 파일 전체를 한 구간으로
        "doc_type": "korean_label",          // §6-1 유형 코드
        "doc_type_ko": "한글표시사항",
        "confidence": "confirmed",           // confirmed | candidate | unknown (§4-5)
        "is_label_candidate": true,          // 한글표시사항 추출 대상 여부
        "is_blocked_non_material": false,    // 비원료 차단 여부(§2-13)
        "mandatory_label_hits": 6,           // 의무표시 7종 중 적중 종 수(§4-1)
        "mandatory_label_threshold": 4,      // "이상(≥)" 경계
        "negative_rule_hit": null,           // 표시사항 배제 음성 규칙 적중 시 유형 코드(§4-1)
        "type_keyword_hits": ["원재료명","품목보고번호","소비기한","내용량","식품유형","보관방법"],
        "sub_tags": [],                      // 하위 태그(§6-2): radioactivity/pesticide_residue/
                                             //   customs/mfds/food_report/hf_report/halal/kosher/
                                             //   organic/facility_certificate:gmp|haccp|iso
        "extracted_fields": {                // §5-3 (없으면 null)
          "lot": null,
          "manufacture_date": null,
          "expiry_date": "2027-06-30",
          "test_date": null,
          "issuer": "○○식품(주)",
          "product_name": "녹차추출물"
        },
        "cross_check": {
          "ingredient_name_input": "녹차추출물",   // 담당자 입력(포털 ingredient_name)
          "name_match": true,                      // 품목명 대조 결과(§5-1)
          "is_abbreviation_suspect": false,        // 약어·코드명 의심(S3)
          "issuer_vs_vendor_mismatch": false       // 발급주체 vs 업체 대조(§5-2)
        },
        "needs_human_review": false,         // 미상/경고 시 true (원칙 4·5)
        "notes": ""                          // 경합·플래그 등 담당자용 메모
      }
    ],
    "overall_needs_human_review": false      // 세그먼트 중 하나라도 review면 true
  }
}
```

**유형 코드 (`doc_type`) — 실질 13종 + `unknown`:**

| 코드 | 한글 | 주요 하위 태그(sub_tags) |
|---|---|---|
| `korean_label` | 한글표시사항 | — |
| `coa` | 시험성적서/COA | `radioactivity`(방사능), `pesticide_residue`(잔류농약) |
| `certificate_of_origin` | 원산지증명서 | — |
| `import_declaration` | 수입신고필증/수입신고확인증 | `customs`(관세청), `mfds`(식약처) |
| `manufacture_report` | 품목제조보고서/품목제조신고서 | `food_report`(일반식품), `hf_report`(건강기능식품) |
| `spec` | 규격서(SPEC) | — |
| `msds` | MSDS | — |
| `certificate` | 인증서(할랄·코셔·유기) | `halal`, `kosher`, `organic`, `facility_certificate`:`gmp`·`haccp`·`iso` |
| `supplier_declaration` | 공급자 선언서/확인서 | `non_gmo`, `bse_tse`, `allergen` |
| `nutrition_analysis` | 영양성분 분석서 | — |
| `process_flow_chart` | 제조공정도 | — |
| `composition` | 원료 조성표/구성비 | — |
| `non_material` | 비원료(차단) | `purchase_order`, `statement`, `tax_invoice`, `quotation`, `proposal`, `invoice`, `packing_list`, `delivery_note`, `biz_license` |
| `unknown` | 기타/미상(폴백, 실질 유형 아님) | — |

- **원칙 정합:** `is_label_candidate`가 시스템의 자동 판정이지만 `operator_confirmed`
  (포털 ④)가 최종 결정이다. `needs_human_review`/`overall_needs_human_review`가 true면
  담당자·내부 큐가 반드시 확인한다. 원본은 `source_hash`로만 참조하고 저장·변형하지 않는다.

## 7. 개발 체크리스트 (요약)

- [ ] §4-1 의무표시 강조합 채점 함수(결정적, 4종 이상) + **음성 규칙**(배합비율/제조방법·SPEC 범위값·LOT+Result+판정) — 회귀 테스트로 S1·S5 케이스 고정
- [ ] §4-1 단독 일반어(유형·소재지·중량·용량·원료명) 미사용 검증 — 조성표·성적서 오분류 회귀 테스트
- [ ] §4-2 유형별 키워드 사전(§2 기반, 13종) — S2 키워드(명세표·전자거래·전자세금) + 신규 유형(제조공정도·조성표·선언서) 포함 확인
- [ ] §4-2 동점 처리 = 강신호 우선 → 경합 시 `미상`("한글표시사항 무조건 우선" 없음) 검증
- [ ] "Certificate"·"Nutrition Facts" 단독 판정 금지 회귀 테스트(COA·원산지·표시사항과 충돌 케이스)
- [ ] 수입/품목/인증 하위 태그(customs·mfds / food_report·hf_report / halal·kosher·organic·facility_certificate) 부여 로직
- [ ] §4-3 첫 페이지 0점 시 마지막+중간 페이지 추가 샘플링 / §4-4 합본 PDF 페이지 단위 재채점
- [ ] §4-5 신뢰도 3등급(경계 "이상") + §1-4 미상 폴백(제출 미차단)
- [ ] 파일명은 판정 로직에 미투입(§1-1) — UI 표시용만, 코드 경로에서 파일명 미참조 검증
- [ ] §5 교차검증(약어 의심·발급주체 대조) — S3·S6 케이스 고정
- [ ] §6 `classification` 블록을 포털 제출 JSON에 병합(필드명 충돌 없음 확인)
- [ ] 규정 수치·법 조항은 분류 로직에 박지 않음(§1-8) — 품목제조보고/신고 근거 조항은 "확인 필요"
