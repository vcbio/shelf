# 헬스푸드 데이터랩 도메인 분리 계획

2026-10-02 작성. 도메인 구입·DNS 변경·실제 이전은 아직 하지 않았습니다.

## 권장 방식

데이터랩 전용 저장소를 만들고 `datalab.vitacoreplatform.com`을 연결합니다. 저장소 이름은 `vcbio/healthfood-datalab`을 제안합니다. 현재 수집 서버와 원문 보관은 유지하고, 데이터랩의 게시 대상만 새 저장소로 바꿉니다. 다른 책장 문서와 VC 플랫폼 앱은 이동하지 않습니다.

처음에는 지금 공개된 데이터랩과 동일한 파일을 옮겨 대조합니다. 데이터 수집 방식까지 동시에 바꾸지 않아야 주소 문제와 자료 문제를 구분할 수 있습니다.

## 옮길 범위

- 데이터랩 첫 화면과 메뉴, 영문 로고·글꼴·용어 안내.
- 등록 원료 631개 상세, 분류·제조신고 연결, 날짜별 검색·예측·구매층 참고 자료.
- 홈쇼핑·유튜브·쇼핑몰의 현재 공개 자료와 화면이 실제로 읽는 과거 자료.
- 주간 보고서 목록·각 보고서·월요일 생성 및 게시 작업.
- 첫 화면 모션그래픽은 장면 구성안 확인과 제작 완료 후 별도로 반영합니다.

현재 게시 스크립트는 책장의 HTML·첨부 문서를 함께 포함합니다. 분리 때는 데이터랩 화면에서 필요한 파일 목록을 만들고, 그 목록으로만 새 사이트를 구성합니다. 경로를 조합해 불러오는 연령·성별·검색 이력과 제품 분할 파일도 포함해야 합니다. 사용하지 않는 옛 파일이라고 추측해서 원문을 지우지 않습니다.

## 작업 순서와 예상 일정

아래는 작업 예상치입니다. 시작일은 도메인 구입과 새 저장소 관리 권한을 확인한 날로 잡습니다.

|순서|작업|예상|
|---|---|---|
|1|필요 파일 목록 고정, 새 저장소와 독립 게시 환경 준비|1일차|
|2|주소 상수·상대 링크·수집 서버의 게시 대상 교체, 임시 주소에서 PC·휴대폰 대조|2일차 오전|
|3|사용자 도메인 등록·DNS 연결·HTTPS 확인, 기존 주소의 이동 안내 적용|2일차 오후부터|
|4|첫 일일 갱신과 다음 월요일 보고서 게시 확인|이전 직후 및 다음 월요일|

구현 작업은 약 2영업일을 예상합니다. DNS 전파와 HTTPS 준비 시간은 별도입니다. GitHub 문서는 DNS 전파와 HTTPS 설정 준비에 각각 최대 24시간이 걸릴 수 있다고 안내합니다. [GitHub 공식 안내](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site)

## 도메인 연결

1. 도메인 소유 확인 후 새 저장소의 Pages 설정에 `datalab.vitacoreplatform.com`을 먼저 등록합니다.
2. 도메인 관리 화면에서 `datalab`의 CNAME 대상을 `vcbio.github.io`로 설정합니다. 저장소 이름이나 `/shelf` 경로는 CNAME 값에 넣지 않습니다.
3. 실제 DNS 응답과 HTTPS 인증서가 준비됐는지 확인합니다.

위 순서는 GitHub의 하위 도메인 설정 안내를 따릅니다. Actions 방식으로 게시할 때는 저장소에 CNAME 파일만 추가하는 것으로 도메인 설정이 끝나지 않습니다. [하위 도메인 설정 원문](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site#configuring-a-subdomain)

## 이전 완료 판정

- 새 주소의 390·1440 화면, 원료 선택·검색·비교·관심·주간 보고서·AI 견적 링크가 정상입니다.
- 데이터랩 파일의 개수·해시가 이전 전후 일치하고 자료 요청 404가 없습니다.
- 새 저장소에 원문 수집 키·토큰·다른 책장 문서가 들어가지 않습니다.
- 수집 서버가 새 저장소에 게시하고, 이전 대기 파일이 옛 주소를 덮어쓰지 않습니다.
- 기존 책장 데이터랩 주소에서 이동할 때 원료 ID·주차·기간·화면 위치를 보존합니다.
- 문제가 있으면 기존 사이트를 계속 사용하도록 게시 대상과 링크를 되돌립니다. 전환 검증 전 기존 사이트를 삭제하지 않습니다.

## 방문 분석 확인 결과

2026-10-02 공개 데이터랩 HTML에서 `gtag`, Google Tag Manager 주소, GA4 측정 ID를 찾지 못했습니다. 실제 브라우저에서도 Google Analytics 요청 0건, `window.gtag` 미정의, `dataLayer` 0개였습니다. 현재 화면에서 GA4 방문 이벤트가 전송된다는 근거는 없습니다. 과거의 별도 GA 계정·속성에 저장된 기록은 계정에 접근하지 않아 확인하지 못했습니다.

GA4가 연결되면 [Google Analytics](https://analytics.google.com/)에서 해당 속성을 고른 뒤 **보고서 → 실시간**으로 들어가 확인합니다. 지금은 측정 ID와 대상 속성을 먼저 확인해야 합니다. 도메인을 옮긴 뒤에도 데이터랩 방문과 AI 견적 이동을 구분해 볼 수 있도록 설정할 계획입니다. [Google 실시간 보고서 안내](https://support.google.com/analytics/answer/9271392?hl=ko)
